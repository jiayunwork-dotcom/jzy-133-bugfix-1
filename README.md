# SPC 均值–极差控制图工具

面向精密轴类零件车间的浏览器端统计过程控制（SPC）系统：录入外径测量值，
**均值–极差（X̄–R）控制图当场更新，Nelson 判异规则实时标色**，过程能力指数
（Cp/Cpk）按基准期冻结统计量给出。

- 后端：Go 1.22 + Echo + PostgreSQL 16（`lib/pq`）
- 前端：Vue 3 + Vite（纯 SVG 自绘控制图，无图表库），nginx:1.27-alpine 托管
- 编排：`docker compose` 三容器（backend / frontend / postgres）

---

## 2. 核心概念与工作流

**监控对象（target）**：一台机床的一个尺寸。单独建档，配置：
规格上限 USL、规格下限 LSL（**允许只填单侧**）、子组容量 n（2~10）、
启用哪些判异规则（4 条可单独开关）。

**测量点入序 → 切组**：测量值是全局点序（`measurements.seq`）。两种录入方式：

1. **自动分组（流式）**：逐个输入或粘贴一列数（空格/逗号/换行/制表符分隔），
   数量任意，按服务器点序连续入序，每凑满 n 个点切一个子组。不足 n 个留在
   「待成组散点」里，下次提交自动在队头续拼。
2. **整组提交**：页面给出 n 个输入框，本次必须恰好 n 个值，单独成一组。
   若该档流式录入还留着散点，整组提交会被拒绝（否则检验员会误以为自己提交的
   值就是一个完整子组），提示先补齐或改用自动分组。

**两阶段控制限**：

1. 先录入 **至少 20 个子组**，在「基准与过程能力」面板指定基准期（起止组号）
   点「冻结控制限」。后端用基准期子组算出 X̄̄、R̄、UCL/LCL（Xbar 图与 R 图）
   并**冻结入库**，同时算出基准期 Cp/Cpk。
2. 之后新录入的子组**只按冻结限判定，绝不回算**。
3. **重新基准必须显式发起**。旧限自动关闭并留档（带生效区间 `effective_to`），
   新限从「基准期结束组 + 1」起生效。历史子组与历史告警仍挂在当时生效的限上，
   图上用竖虚线标注重新基准备分界，每段控制限各自画出。

**判异（Nelson 1~4，只作用于 X̄ 图；R 图只展示不判异）**：

| 规则 | 内容 | 触发窗口 |
|---|---|---|
| 1 | 一点超出 ±3σ（严格超出控制限，恰在限上不算） | 1 点 |
| 2 | 连续 9 点落在中心线同侧（恰在中心线上中断计数） | 9 点 |
| 3 | 连续 6 点递增或递减（相邻持平中断） | 6 点 |
| 4 | 连续 3 点中 ≥2 点落在同侧 2σ~3σ 区（恰压 2σ 线计入；3σ 外的点按同侧计入） | 3 点 |

每条规则可在档案上单独开关；每条告警记录 **规则号、触发子组、涉及的全部子组**。

**过程能力**：按基准期、组内标准差估计 σ = R̄/d₂：

- 双侧：Cp = (USL−LSL)/(6σ)，Cpk = min((USL−X̄̄)/(3σ), (X̄̄−LSL)/(3σ))
- 单侧：只给对应侧 Cpk，Cp 留空（前端显示「—（单侧规格）」）
- 存在任何告警点时，指数照常计算，页面标注 **「过程不受控，能力指数仅供参考」**

## 3. 判异评估策略：方案、理由与代价

**选定方案：服务端事务内、对冻结限生效区间做「纯函数从头重放」，告警按键
`(target, rule, triggerSeq)` 幂等合并——只插入新出现的，从不删除旧的。**

实现位于：

- `internal/domain/alarms.go` 的 `Evaluate`：输入「有序均值点 + 冻结的
  center/UCL/LCL + 启用规则集」，输出告警列表。**纯函数、无状态**。
- `internal/service/evaluate.go`：每次切组后取当前开放基准与其生效起点
  （`effective_from`），加载该区间内全部子组，重放，再与库中已有告警键比对。

**为什么这样选**（题目允许三选一：增量窗口状态 / 尾部重评估 / 从头重放）：

1. **一致性天然成立**。规则 2/3/4 都跨窗口依赖历史点，增量维护四套滑动窗口
   状态最容易在并发、重新基准、规则开关变更时累积状态 bug；重放无状态，
   「同一段数据反复评估」由纯函数性质保证完全一致（见
   `TestRepeatedEvaluationDeterministic`）。
2. **在线追加 ≡ 一次性重放**。每次录入等价于「把同一段序列从头再评估一遍」，
   触发键只增不减，因此逐点在线追加累积出的告警集合与对整条序列一次重放的
   结果完全相同（见 `TestOnlineAppendEqualsFullReplay`）。
3. **已出告警不会因后来的点消失**。落库是 `ON CONFLICT DO NOTHING` 的只增
   写入；新点最多让告警键集合变大。唯一例外是重新基准：旧限区间的告警作为
   历史记录保留并挂旧限版本，新限只对新生效区间判异、不回溯旧点。

**代价**：每次录入 O(k)（k = 当前基准生效区间子组数）。车间每 2 小时一个子组，
一年约 1000~3000 点，纯算术重放为微秒级，完全可接受；真正的 I/O 是一次
区间查询。未来若数据量到几十万点，可退化为「尾部缓冲 + 周期全量校验」的
混合方案，接口无需变化。

**重新基准时告警的生命周期**（显式约定）：

- 旧限期间产生的告警**不删除、不按新限重判**，作为历史留档（这正是
  「历史点仍按当时生效的限显示」的告警侧对应物）；
- 新限从 `effective_from` 起对之后的切组生效；
- 首次基准（此前没有任何限）会对生效区间做一次重放，使冻结时刻的状态与
  「当时在线」一致。

## 4. 并发录入如何保证「不丢不重、顺序一致」

`POST /api/targets/:id/ingest` 的整个过程在**一个数据库事务**中执行，第一步就是

```sql
SELECT ... FROM targets WHERE id=$1 FOR UPDATE
```

两个检验员同时往同一档提交时，事务在目标行锁上**串行化**：

- 点序号 `measurements.seq` 用
  `max(seq)+1`（在持锁事务内）分配，两次粘贴的点**不会交错**——一次粘贴的
  整列数在点序上连续；
- 切组从散点队头按 n 个连续切，子组序号连续，`(target_id, subgroup_seq)`
  为主键杜绝重复；
- 提交在组边界（n 的整数倍）原子可见，读端不会看到半个子组。

集成测试 `TestIntegrationConcurrentIngest` 用两个 goroutine 各提 20 个整组，
断言最终恰好 40 组、序号 1..40 连续、每组容量为 n。

## 6. HTTP API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 存活探针 |
| GET | `/api/targets` | 监控对象列表 |
| POST | `/api/targets` | 建档 |
| GET | `/api/targets/:id` | 单个对象 |
| GET | `/api/targets/:id/series` | **主图全量数据**：点（含归属限版本）、全部限段（含留档）、告警、能力 |
| POST | `/api/targets/:id/ingest` | 录入：`{"values":[...], "grouped": false|true}` |
| POST | `/api/targets/:id/baselines` | 发起/重新基准：`{"startSeq":1,"endSeq":20}` |

建档请求：

```json
{
  "name": "主轴外圆 Φ20", "machine": "CNC-07", "dimension": "外径",
  "usl": 20.05, "lsl": 19.95,
  "subgroupN": 5,
  "enabledRules": [1, 2, 3, 4]
}
```

`usl`/`lsl` 传 `null` 或省略表示该侧无规格。所有错误统一为
`{"error": "中文原因"}`，校验类错误 HTTP 400，对象不存在 404。

## 7. 校验清单（前端即时提示 + 后端最终裁决，两边措辞一致）

| 场景 | 提示要点 |
|---|---|
| 测量值不是数字（字符串 / 布尔 / NaN / 空） | 「第 k 个值「x」不是有效数字」；API 层自定义 JSON 解码拒绝非数字类型 |
| 子组容量与档案不符（整组数量 ≠ n） | 「本次提交 x 个值，但档案子组容量为 n」 |
| 上限不大于下限 | 「规格上限(x)必须大于规格下限(y)」 |
| 规格两侧都不填 | 「规格上下限至少填写一侧」 |
| n 不在 2~10 | 「子组容量必须是 2 到 10 之间的整数」 |
| 基准期子组 < 20 | 「基准期至少需要 20 个子组，当前仅 k 个」 |
| 基准结束组超出已有数据 | 「基准期结束子组(第k组)超出已有数据(当前共m组)」 |
| 整组提交但有未凑满散点 | 「该档尚有 k 个未凑满的散点，请先在流式模式补齐或改用自动分组」 |

## 8. 如何核对（与验收点逐条对应）

### 8.1 领域单测（无需数据库）

```bash
cd backend && go test ./...
```

- **Cp/Cpk 关系**（`domain/domain_test.go::TestCapabilityRelations`）：
  均值在规格中心时 Cpk = Cp；规格宽度加倍（6→12）数据不变，Cp 1→2；
  均值平移 10→11，Cp 保持 1、Cpk 降为 2/3；单侧规格只有 Cpk；σ=0 时
  两个指数都为空。
- **每条规则的「恰好触发 / 差一点」**（同文件 `TestRule1..4`）：
  - 规则1：19.0001 触发，恰在 UCL=19 不触发；
  - 规则2：连续 9 点触发（涉及 1~9），8 点不触发，中心线点/两侧交替中断；
  - 规则3：6 连增/连减触发，5 点不触发，持平、先增后降中断；
  - 规则4：3 点中 2 点在同侧 2σ 区触发，1 点不触发，分居两侧不触发，
    恰压 2σ 线（16）计入、15.99 不计入。
  - 规则关闭时一律不评估。
- **在线追加 = 从头重放**：`TestOnlineAppendEqualsFullReplay`
  逐点累积告警键集合，与一次性重放逐条比对完全相同；并验证早期告警
  （第 12、18 点的规则 1）在后续点加入后仍保留。
- **基准统计/控制限常数**：`TestSubgroupBaselineAndLimits` 对 n=5 的 25 组
  数据核对 X̄̄、R̄、UCLx = X̄̄ + A2·R̄（A2=0.577）、UCLr = D4·R̄（D4=2.114）、
  σ = R̄/d₂（d₂=2.326）。

### 8.2 PostgreSQL 集成测试（并发 / 冻结 / 重新基准）


- `TestIntegrationConcurrentIngest`：两检验员并发 40 个整组 → 40 组连续、
  不丢不重（对应验收点 6）。
- `TestIntegrationStreamingGroupsByServerOrder`：3 散点 + 粘贴 6 个 →
  [1..4]、[5..8] 切两组、残留 1 个；再补 3 个 → 残留点 9 排在新组队头

- `TestIntegrationBaselineFreezeAndRebaseline`：
  - <20 组发起基准被拒；
  - 冻结后录越界点，**限数值不变**（不回算），产生恰好 1 条规则 1，

1. 建档后录 20 组 → 填基准期 1~20 → 「冻结控制限」，图上出现 CL 与橙虚线

## 9. 关键设计备注

- **规则只判 X̄ 图**：题目指定的四条 Nelson 规则在实现上全部基于均值点；
  R 图保留 UCL/CL/LCL 供人工发现变异增大，但不产生告警。
- **控制限退化（基准期 R̄=0）**：σ 为 0 时规则 2/3/4 无可靠分区，规则 1
  仍按严格越限判定；Cp/Cpk 为空。正常有变异的过程不受影响。
- **首次基准生效起点 = endSeq+1**：基准期子组本身是「参考点」，不按由自己
  算出的限判异，图上画为灰色点；这样也保证基准期内的点不会凭空制造大量
  规则 2 告警。
- **迁移**：SQL 嵌入二进制，启动时按文件名顺序应用并登记到
  `schema_migrations`，每个迁移独立事务。
- **时间/序号**：全部判定只依赖子组序号这一全序，不依赖墙上时钟，因此
  多检验员并发、批量补录时判异结果仍然确定。
